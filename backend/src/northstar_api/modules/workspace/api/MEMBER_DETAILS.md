# Workspace member details (incremental)

`GET /api/v1/workspace/members/details` (and the existing `/v1` alias) uses the normal bearer authentication, selected `X-Workspace-ID`, entitlement guard, and `members.view` permission. It returns **only active global user accounts with a membership in the selected tenant AND selected workspace**. The response is a JSON array (empty `[]` for an empty membership list). An unauthorized or nonexistent selected workspace is denied by principal resolution. The route is read-only and does not alter existing member/invitation contracts.

Response fields for each member: `userId`, `name`, `email`, `role`, `status` (`active` or `suspended` in this workspace), `mfaEnabled`, `lastLoginAt`, `invitedByUserId`, and `joinedAt`. `mfaEnabled` and `lastLoginAt` are existing *global account* properties, **not a workspace-specific MFA policy or last Workspace activity**. The frontend labels account last sign-in accordingly. `invitedByUserId` uses a same-tenant, same-workspace, accepted invitation whose `acceptedByUserId` matches the member; it is `null` if no reliable invitation record exists. Invite tokens and password material are not returned. `joinedAt` comes from the workspace membership, not the account creation timestamp.

The endpoint does not fabricate team memberships, last workspace activity, or workspace MFA enforcement: those need authoritative feature-specific persistence and enforcement. The Members screen retains legacy invite, edit, remove and agent scope controls, plus the separate lifecycle panel; detail table adds a manual Refresh control after administrative changes, and handles loading, empty and error/retry states. The caller's workspace selection is checked by the existing context-safe API client and the component is remounted when context changes.

Regression coverage added at `backend/tests/test_workspace_member_details_api.py` (scope, schema, inviter after real invite/signup) and `frontend/src/features/workspace/members/WorkspaceMemberDetailsPanel.test.tsx` (labels, data, error/retry). These tests are **committed but not verified passing**; full dependency installation/CI, migration and browser validation remain required before accepting Members/Invitations. No existing database tables or routes were deleted or replaced.
