# Workspace feature module — incremental migration

This directory owns new workspace capabilities without deleting or relocating existing implementation. The public API remains `GET/PATCH /api/v1/workspace` (with the existing `/v1` alias); authentication, workspace selection (`X-Workspace-ID`), permission enforcement, validation, legacy branding, security, members, invitations and API keys continue through the existing routers. This module is **not** a replacement workspace router yet.

## General settings — implemented code, acceptance pending

`services/general_settings.py` is called by `northstar_api.routers.workspace.update_workspace` after existing validation and before the existing database commit. It compares persisted `name`, `slug`, `timezone`, `default_language`, `date_format`, and extended preferences; it records only genuinely changed field names. It stages a `workspace.settings.updated` audit record (actor, tenant and workspace IDs) and a `workspace.settings.updated.v1` outbox record (tenant and workspace IDs) in the same transaction. On transaction failure, the workspace change, audit record and event roll back together. Outbox payload: `{ "workspaceId": "<UUID>", "fields": ["name", "timezone"] }`. **Old and new values, access tokens and secrets are not included.** Unchanged general settings do not produce a domain event. Legacy security and branding paths retain their pre-existing events and behavior.

The existing `GET /api/v1/workspace` response and `PATCH /api/v1/workspace` request/response schemas remain compatible. `WorkspacePreferences` extends its original timezone, language and date format with industry, country, description, time format, three-letter currency, week start, workspace icon and validated seven-day business hours. The new profile persists in the existing workspace `settings_json.preferences`; the original timezone, language and date columns remain synchronized. Workspace creation can include the expanded settings. There is no destructive migration or new external service.

**Backward compatibility:** `services/preference_merge.py` merges only explicitly supplied PATCH fields, including nested day properties. An older client sending just timezone/language/date format cannot erase an extended profile or business hours. It revalidates the merged profile. Invalid old stored values are displayed with safe defaults without silently mutating the database. Business hours are **reference data only**; this change does not enforce channel operating hours, automatically reply, or change conversation routing.

The original Workspace page still renders the existing General Settings form, now delegated to `frontend/src/features/workspace/general/WorkspaceGeneralPanel.tsx` with the extended form in `WorkspaceGeneralDetails.tsx`. It continues to call `workspaceApi.update`. Users lacking `workspace.update` receive read-only controls while the backend remains the authorization authority. Workspace changes invalidate an in-flight form load/save display, and failed initial reads show an error and retry action. Existing team, developer, security, billing and White Label entries are preserved.

Run full backend suite and full frontend lint, typecheck, tests and build (`frontend/package.json`). Cover wrong-workspace access, permission denials, changed fields, old-client partial PATCH preservation, nested hours, transaction rollback and pre-existing feature regressions. Verify same-SHA CI and deployed behavior before merging.

The **20 focused backend unit tests** for general-setting change detection, extended profile validation and partial preference merge passed in an isolated environment with audit/outbox dependencies mocked, using files checked against GitHub content hashes. The committed HTTP/database integration tests and frontend component/race tests are **not verified as passing**. A source-matched TSX syntax transpilation check succeeded but is not a full TypeScript typecheck. GitHub Actions reports failures without accessible job steps or assigned runners, so the cause and full-suite results are unknown. No production deployment has been performed.
